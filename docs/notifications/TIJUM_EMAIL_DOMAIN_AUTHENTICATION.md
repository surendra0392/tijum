# TIJUM Domain Email Authentication & DNS Configuration Guide

## 1. Overview

To ensure high inbox placement, protect brand reputation, and comply with Gmail and Yahoo 2024/2026 sender requirements, all transactional emails dispatched by `mail.tijum.com` must pass **SPF**, **DKIM**, and **DMARC** validation.

This guide details the exact DNS records and mail server configurations required for `tijum.com`.

## 3. Required DNS Records

### A. Sender Policy Framework (SPF) — ACTIVE & VERIFIED
The SPF record identifies authorized servers and relays permitted to send email on behalf of `@tijum.com`.

- **Live DNS Value on `tijum.com`:**
  ```text
  v=spf1 +a +mx include:relay.mailbaby.net ~all
  ```
- **Status:** **PASS / ACTIVE**
- **TTL:** `3600`
- **Scope:** Authorizes server A records, domain MX records (`mail.tijum.com`), and relay gateway with softfail protection.

---

### B. DomainKeys Identified Mail (DKIM) — CONFIGURED & ACTIVE
DKIM provides cryptographic signature verification confirming that the email was sent by the domain owner and was not modified in transit.

- **Status:** **✓ CONFIGURED (VERIFIED)**
- **Coverage:** Active on `mail.tijum.com` across all domain mailboxes:
  - `admin@tijum.com` — Configured
  - `bookings@tijum.com` — Configured
  - `grievance@tijum.com` — Configured
  - `info@tijum.com` (Catch-All) — Configured
  - `no-reply@tijum.com` — Configured
  - `notifications@tijum.com` — Configured
  - `sales@tijum.com` — Configured
  - `support@tijum.com` — Configured
- **Signing Mechanism:** Every outbound transactional email dispatched via `no-reply@tijum.com` (or other departmental senders) receives an automatic cryptographic DKIM signature header (`DKIM-Signature`) generated by the mail transfer agent.

---

### C. Domain-based Message Authentication, Reporting & Conformance (DMARC) — ACTIVE & VERIFIED
DMARC aligns SPF and DKIM authentication, directing recipient mail systems how to handle unauthorized emails and providing delivery telemetry.

- **Live DNS Value on `_dmarc.tijum.com`:**
  ```text
  v=DMARC1;p=quarantine;sp=none;adkim=r;aspf=r;pct=100;fo=0;rf=afrf;ri=86400
  ```
- **Status:** **PASS / ACTIVE (QUARANTINE ENFORCED)**
- **Policy Breakdown:**
  - `p=quarantine`: Protects domain reputation by sending non-compliant spoofed messages to spam/quarantine.
  - `sp=none`: Subdomain policy flag.
  - `adkim=r` & `aspf=r`: Relaxed alignment for DKIM and SPF.
  - `pct=100`: Applies quarantine enforcement to 100% of outbound messages.
  - `ri=86400`: 24-hour reporting interval.

- Contact the hosting / VPS provider (or configure via cloud ISP console):

  - **Reverse DNS (PTR):** `mail.tijum.com`
- Test rDNS lookup:

## 5. Deliverability Best Practices & Hygiene

1. **RFC 8058 One-Click Unsubscribe:**
   Non-critical transactional emails include automated `List-Unsubscribe` and `List-Unsubscribe-Post` headers:
   ```http
   List-Unsubscribe: <mailto:support@tijum.com?subject=unsubscribe>, <https://tijum.com/notifications/preferences>
   List-Unsubscribe-Post: List-Unsubscribe=One-Click
   ```
2. **Warm-Up Schedule:**
   Because `mail.tijum.com` uses a dedicated IP, begin with transactional emails (OTP, password reset, reservation confirmations) before sending batch or promotional announcements.
3. **Blacklist Monitoring:**
   Regularly monitor IP `103.191.209.159` against Spamhaus, Barracuda, and SORBS using mxtoolbox.com.
